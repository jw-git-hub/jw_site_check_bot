# Памятка владельцу: @jw_site_check_bot

Адрес, пользователь и путь сервера здесь не пишутся — репозиторий публичный. Они в `deploy/deploy.local.env`
на Маке. Ниже «папка бота» — путь оттуда (`DEPLOY_PATH`), в командах — всегда в кавычках.

## Команды бота

| Команда | Кто | Что |
|---|---|---|
| `/start` | все | приветствие; `/start <метка>` записывает источник |
| `/lang` | все | язык |
| `/about`, `/order` | все | кто сделал, как заказать |
| `/stats` | вы | учёт по меткам за 7 и 30 дней |
| `/site <домен>` | вы | последние проверки домена: откуда человек, что он видел в отчёте |

Ссылки с меткой: `https://t.me/jw_site_check_bot?start=channel` — канал, `…?start=site` — сайт,
`…?start=grp_danang` — группа Дананга и так далее: латиница, цифры, `_` и `-`.

## Сервер — один раз

1. Docker и nftables (sudo):
   ```bash
   sudo apt update && sudo apt install -y docker.io docker-compose-v2 nftables
   sudo usermod -aG docker "$USER"   # затем выйти и зайти по SSH заново
   ```
2. Репозиторий — вне папок Syncthing (если папки бота ещё нет):
   ```bash
   git clone https://github.com/jw-git-hub/jw_site_check_bot.git "<папка бота>"
   ```
3. `.env` — только руками и только здесь; папка `data` — пользователю контейнера (uid 10001):
   ```bash
   cd "<папка бота>"
   [ -f .env ] || cp .env.example .env   # уже есть — остаётся как есть
   chmod 600 .env && nano .env           # BOT_TOKEN, PAGESPEED_API_KEY, ADMIN_ID
   mkdir -p data && sudo chown 10001:10001 data
   ```
4. Изоляция сети: `sudo deploy/firewall.sh`.
5. Первая выкладка — с Мака: `deploy/deploy.sh`.
6. Проверка изоляции — на сервере: `deploy/check_isolation.sh`. Повторять после перезагрузки сервера и после
   `sudo systemctl restart tailscaled docker`.

## Выкладка и откат

- С Мака, из папки проекта: `deploy/deploy.sh` — выкладывает то, что уже в GitHub.
- Откат: `deploy/deploy.sh <sha прошлого коммита>` (`git log --oneline`).
- Из поездки — так же: в `deploy.local.env` стоит имя сервера в Tailscale, достаточно включить Tailscale на Маке.
  Если выкладка остановилась с сообщением про связь с сервером — это тот случай: включите Tailscale и повторите.

## Жизнь бота

- Состояние: на сервере `cd "<папка бота>" && docker compose ps`.
- Журнал: `docker compose logs --tail 100 bot`.
- Открыть бота всем: в `.env` на сервере `OPEN_TO_ALL=true`, затем `docker compose up -d`.
- Лимиты: `USER_DAILY_LIMIT`, `GLOBAL_DAILY_LIMIT` в `.env`, затем `docker compose up -d`.
- Копии базы: `data/backups/` — по одной в сутки, 7 последних.
- Перезапустили nftables (`sudo systemctl restart nftables`) — это останавливает и Docker (так устроено
  нарочно, без таблицы контейнер не работает): `sudo systemctl start docker`, затем `deploy/check_isolation.sh`.
- `systemctl reload nftables` или чужой `nft flush ruleset` снимает таблицу изоляции молча — после них
  `sudo deploy/firewall.sh` и `deploy/check_isolation.sh`.

## Сообщения от бота вам

| Сообщение | Что делать |
|---|---|
| «PageSpeed отказал: закончилась квота ключа» | подождать до обновления квоты; если часто — проверить `/stats`, нет ли злоупотребления |
| «PageSpeed не принял ключ» | новый ключ в Google Cloud (только PageSpeed Insights API) → в `.env` → `docker compose up -d` |
| «PageSpeed отвечает не так, как надо (…)» | подождать; если сбой держится, сообщение повторится через 6 часов. В скобках — причина |
| «Сработал общий потолок» | `/stats`: наплыв людей — поднять `GLOBAL_DAILY_LIMIT`; всё с одной метки — разобраться с источником |
| «В ответе PageSpeed … нет проверок» | Lighthouse обновился: поправить `AUDIT_IDS` (план, задачи 10–11) |
| «Не удалось узнать внешний адрес дома» | проверить интернет на сервере; бот повторит через час. Пока адреса нет, сайт, ведущий на адрес дома, бот не отличит от чужого |

## Если ключ утёк

1. Токен бота: @BotFather → `/revoke` → новый токен в `.env` на сервере → `docker compose up -d`.
2. Ключ PageSpeed: удалить в Google Cloud, выпустить новый с тем же ограничением → `.env` → `docker compose up -d`.
3. Если секрет попал в git: не «удалять следующим коммитом» — сначала перевыпустить ключ, потом разбираться
   с историей.
